# 布局关系与响应式

用于 Figma 布局细化、实现设计稿、手机适配和长文案溢出问题。

## 1. 先按用途分类元素

| 元素类型 | 优先处理方式 | 需要避免 |
| --- | --- | --- |
| 营销用的 UI 拼合、插画、结果卡组 | 建立统一构图坐标，再整体等比缩放或按明确规则简化 | 将每个装饰控件放大到可操作尺寸，破坏构图 |
| 真实表单、导航、按钮、弹窗 | 根据可操作性、内容和空间重排 | 整页缩小导致文字或点击区域不可用 |
| 正文、FAQ、价格说明 | 自然排版，控制行长与层级 | 固定高度截断，强行复用另一语言的换行 |
| 产品与场景照片 | 保持比例，按主体决定 object-position | 所有断点机械居中裁切 |

同一区块可以同时包含以上类型。例如首屏外层标题需要正常响应式，右侧营销组合画面可以作为整体缩小。

## 2. 写出布局关系

对核心容器明确：方向、对齐、间距、内边距、宽高策略、最小值、最大值、溢出和定位基准。

Figma 与代码的对应关系应保持意图，而非逐个复制坐标：

- Hug 对应按内容确定尺寸；Fill 对应使用可用空间并允许必要收缩。
- Auto Layout 的 gap 与 padding 分开；一个用于元素关系，一个用于容器边界。
- 可伸缩的 Grid / Flex 子项需要检查最小宽度、长文本换行和 intrinsic size。
- 绝对定位适合装饰画面的局部构图；实际表单和正文优先使用文档流。
- 圆形头像与介绍卡先作为一组建立关系，再让各组形成错落布局。
- 固定宽度只用于确有固定尺寸的对象，不能用来掩盖内容约束缺失。

对于装饰性组合画面，保留原始构图宽高或比例，让外层按缩放后的真实尺寸参与布局。只做 transform 却仍保留原始占位高度，容易造成手机上大段空白。

执行时分别记录原构图宽高、展示宽度和等比比例：`缩放比例 = 展示宽度 / 原构图宽度`，外层占位高度跟随 `原构图高度 × 缩放比例`。所有装饰子项以同一构图容器为坐标基准。用户只手调位置并要求保留缩小后的尺寸时，单独合并位置和尺寸，不整体回退到手调稿的旧宽高。

卡片里的真实输入框与按钮按关系分配宽度：先扣除父级 padding 和 gap；按钮按文字与内边距占位；输入框使用剩余空间并可收缩。实现可使用 `min-width: 0`、`minmax(0, 1fr)` 或合适的 Flex 约束；空间不足时切成上下排列。不要同时给二者固定宽度，也不要仅在最外层截断溢出。

## 3. 从真实内容推导断点

先检查用户主要设备与现有设计，再在布局开始失效的位置调整。常见检查宽度可以从约 320、390、768 和桌面开始；它们是诊断样本，不是每个项目固定的断点规范。

逐区处理：

1. Header：Logo、导航、语言与 CTA 共同占宽；手机是否收进菜单由项目决定。
2. Hero：标题行数、行高、画面高度与装饰组比例一起检查。
3. 卡片与产品区：列数变化后，图片比例和文案空间仍成立。
4. Tab：使用换行、横向滚动或另一布局时，保留清晰的选中与切换行为。
5. 表单：字段宽度、标签、错误提示和按钮不能互相挤压；必要时按整行排列。
6. 弹窗：高度受视口约束，内容可滚动，标题与关闭 / 返回入口可发现。
7. Footer：按语义分组重排，社媒与返回母站入口不会遗漏。

## 4. 处理常见细节缺陷

### 图标贴边

区分文字 padding 与图标定位。增加 select 的右侧文字 padding 不一定移动浏览器默认箭头。若需自定义，移除原生外观并明确图标的 inline-end 间距，为文字预留空间，同时保留原有选择与键盘语义。

输入框、日历、筛选框和后台 select 使用一致的边界关系。项目可采用统一间距 token，但不要把某次修复的 14px 或 16px 变成所有项目标准。

检查分三步：确认实际渲染的是原生箭头还是自定义图标 → 核对控件 `padding-inline-end` 与图标 `inset-inline-end` 是否各自生效 → 在最窄相关尺寸检查文字不压图标、图标与外边框有一致留白。同一问题再次出现时搜索前台表单、后台分类、筛选及状态控件的全部实例，修共享规则或统一差异，不能只修用户截图中的一个。

### 装饰卡片散乱

先修正父容器和元素分组，再调整局部坐标。核心界面缩小后，相邻头像、提示和结果卡也应保持相关距离。核对重复内容和多余浮层。

### 登录页出现滚动

检查视口单位、外边距、header 占位、字体加载与表单实际高度。桌面一屏适配按任务实现；小屏、软键盘、验证错误或放大文字时仍应能访问所有控件，不能用全局 overflow:hidden 把内容裁掉。

### 英文按钮和 Tab 换行

先检查内容、父级约束和 gap，再决定改写或布局调整。不要无条件加 nowrap，让溢出转移到屏幕外；也不要缩小所有文字来挽救少数长标签。

### 手机标题行距过大

用实际目标字体检查字号、行高单位、文本框高度及上下 margin。先去掉沿用桌面固定高度和多余空行，再校准多行标题内部行距；不要把 section 上下留白与标题 line-height 混成同一个值。验收既看行间紧凑度，也看字形无裁切、与下方说明保持明确层次。

## 5. 验收方法

对当前改动选取有意义的设备宽度与至少一个中间宽度。使用实际字体、真实语言、长标题、空数据、较多产品等相关状态。

测量横向溢出并定位具体元素；目视检查首屏比例、局部裁切、上下留白和弹窗边界。“没有横向溢出”只是一个条件，不能证明构图合理。

分开检查三个结果：**页面边界、内容换行、画面主体**。所有区块标题都需要看实际换行；旁边的说明挤压标题时，先让说明在窄屏另起一行，不把全站标题缩小。检查是否出现非设计意图的孤字末行；行数应符合本区块目标，不要求全站一律两行。

大幅场景图在竖屏 cover 后可能裁掉主要产品，即使图片元素宽度完全正常。先选择保住主体的裁切，再检查文案重叠；两者无法兼顾时，将手机文案和图片分成独立区域、改变图片占位或使用合适的另一素材。保存修正前后相同宽度的画面，不用“无溢出”代替这一项。

SaaS 产品截图也需要按内容选取焦点。整张缩小可能只剩不可辨认的小字，机械裁切则可能切断一条反馈、金额或状态。手机可以从同一素材导出完整的关键列表或详情区域，保留其要证明的关系；不重画出素材中没有的产品能力。截图中的控件仍是展示，真实体验入口单独提供并保持可操作尺寸。

有真实交互的区域实际操作一次，包括手机菜单、日历、表单、产品详情与返回。装饰性画面则检查整体比例，不把其中的假想控件当成真实操作目标。
