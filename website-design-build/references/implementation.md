# 工程实现与设计接入

用于在既有代码库实现设计、建立新站、更新素材或接入必要网站能力。

## 1. 读取现有项目

确认 repo、工作目录、相关指令、当前分支、未提交修改、框架、应用入口、构建命令、路由和部署方式。局部任务只读相关代码；整体任务再扩展检查。

在 monorepo 中识别官网、登录、主产品、共享设计系统、地区 app 和数据服务各自归属。历史 PR 是已有行为线索，不自动成为本次可修改范围。

用户指定沿用的 folder、基线和 PR 关系保持不变。发现必须跨层修改时先判断是否已在授权范围内，不因为实现方便顺带改写主产品。

## 2. 读取最新设计

取得当前节点与实际渲染，核对用户手调、素材、字体、断点和状态。需要时将复杂 section 的布局关系记录在规格中。

区分：

- 页面内容和营销文案。
- 共享组件的外观与接口。
- 应用层的组合、尺寸与布局。
- 既有业务回调、数据和权限。

优先修正发生问题的层。例如卡片容器太窄通常先调整消费页面布局；不要为单页问题改变共享按钮的全局行为。

## 3. 复用已有能力

搜索项目已有的按钮、输入框、语言组件、图标、弹窗、菜单、登录和表单模式。复用公开接口及约定，保留 loading、disabled、focus、键盘、错误和成功行为。

确无合适组件时再实现局部组件；不要只因截图方便重造通用控件。也不强制把所有一次性营销区块抽象成公共库。

新站没有既定栈时，根据页面行为、编辑方式、动态数据和部署环境选择简单可维护的实现。需要后台和数据不意味着必须用某一家平台；核对当前服务能力、账号归属与现有资源后再接入。

## 4. 接入素材与网页身份

- 建立可追溯的素材文件名和用途，保留所需原始文件。
- Logo 在 header、footer、登录、滚动状态、手机菜单和相关语言中按正确组合应用。
- favicon 同步检查实际引用、格式、尺寸和缓存；旧缓存可用新文件名或版本引用处理。
- 产品与场景图片按显示用途导出，控制尺寸、体积与主体裁切；避免仅拉伸低清原图。
- 图标来自真实品牌或现有图标系统；需要统一填色 / 描边时覆盖整组及状态。
- 字体有实际文件或可用来源，检查真实字重与回退效果。
- 修改相关页面时同步适当的 title、description、canonical、分享图、站点图等已有设置；不把局部样式修改扩展成全站 SEO 项目。

提交网页前统计资源实际字节数。保留原图，另导出网页资源；确认未引用的大型原图没有被重复打包。照片可按场景使用合适的压缩格式与显示分辨率；需要透明度或保真细节的素材另行判断。首屏关键图明确尺寸与优先级，非首屏图片按需加载。以实际画质和总负载决定优化，不给所有图片套同一个文件上限。

确认预览链接与生命周期：本地服务、临时预览和已部署站点分别记录。最终链接必须对应已验证版本且在交付时能打开；若要关闭自己启动的本地服务，先确保用户已有可用的托管入口或清楚的本地运行方式。

## 5. 接通路由、接口与动态内容

保证锚点、详情、价格、登录、返回目标与地区路由指向当前应用。检查部署重写、文件路由和静态输出的优先级。

多页新站共享品牌、导航、按钮、输入框与颜色规则，同时保留各页任务差异；登录页不必机械复制官网全部导航。套餐等会跨页出现的数据也应共用来源，具体金额和选择链路按 [转化流程](conversion-flows.md) 验证。部署验收包含价格、登录等子路径的直接访问与刷新，不能只从首页点击后判断路由可用。

本次包含母站到子产品入口时，记录入口所在站点、菜单位置、顺序、图标、名称与目标；不要仅在子产品 footer 加一个链接就认为母站菜单已完成。保留已有市场 / 案例入口，新预留页面不伪装成已存在的内容。按约定走一遍“母站菜单 → 产品官网 → 价格 / 登录 → footer 返回母站”，并分别检查桌面 hover / 点击和手机菜单。

内容从代码迁入后台后，确认前台真正读取已发布数据。静态 index、构建时 JSON、运行时接口与缓存分别判断；数据库更新成功并不保证实际首页已切换数据源。

配置留在适当的环境层，不把密钥或生产私有数据嵌进前端。原有能力的预览配置与正式配置不同时，写清分别验证了什么。

## 6. 验证深度

| 变更 | 最低有意义的检查 |
| --- | --- |
| 字号、间距、图标、文案 | 对应区域渲染、相关断点与已有必要检查 |
| 共享组件、布局约束 | 相关消费者、类型 / 构建、长内容与状态 |
| Tab、日历、弹窗、滚动 | 实际操作、键盘 / 触摸与退出行为 |
| 登录、留资、发布、数据接口 | 请求与响应、权限、成功 / 失败和实际数据结果 |
| 部署与域名 | 对应版本、实际入口、资源、路由与相关流程 |

使用项目已有 lint、build 和相关测试。新增测试覆盖真实规则与可能回归的行为，不为每个 CSS 数值创建断言。先运行足够验证本次修改的检查，发现共享影响或失败后再扩大。

视觉检查与自动测试互补：构建无法判断是否使用了旧 Logo，截图也无法证明表单已持久化。未能验证的部分明确说明，不以模拟结果替代。
