# 交互状态与动效

用于导航、Tab、FAQ、分类与产品弹窗、轮播、渐变材质及滚动叙事。只实现服务于内容理解或操作反馈的运动。

## 1. 先写行为，再选技术

对相关组件明确：触发、默认状态、过渡、结果、取消 / 返回、键盘行为、手机行为。页面里的装饰性 UI 与真实交互分别处理。

| 元素 | 需要明确的行为 |
| --- | --- |
| Header | 顶部与滚动状态、收缩阈值、尺寸与内边距、展开菜单、锚点偏移 |
| Tab / 场景展示 | 选中状态、点击、自动进度、暂停条件、手动切换后的计时 |
| FAQ | 默认展开项、能否同时展开多个、hover / focus、折叠后分隔线 |
| 分类弹窗 | 信息顺序、是否有产品、数量与列表引导、滚动区域、关闭入口 |
| 产品详情 | 图片切换、规格、询盘预填、返回原分类及浏览位置 |
| 自动轮播 | 切换方式、时长、文字是否固定、控制方式与减少动态效果 |

默认展开第一个 FAQ、仅允许一个答案展开、隐藏轮播按钮等都需来自项目要求，不作为所有网站的默认规则。

## 2. 将参考动效拆成参数

先观察参考的运动对象和时序，需要时检查其公开实现；不凭静态截图猜测完整动画。

记录：

- 对象：整体轮廓、内部渐变、局部亮区、模糊、颗粒或内容卡片。
- 变化：位移、范围、颜色、透明度、模糊强弱、比例、遮罩。
- 时序：开始条件、速度、停留、切换、循环衔接。
- 约束：固定不动的部分、品牌色域、最高 / 最低明暗、裁切范围。
- 输入：点击、hover、滚动、键盘、触摸，是否会互相覆盖。
- 降级：减少动态效果设置、低性能设备或静态展示时保留的信息。

例如“轮廓保持固定，内部浅色渐变流动，亮白区域范围缓慢变化，局部模糊有差异并带轻颗粒”，与“整个图形旋转”是不同效果。用户要求更明显时，先调变化范围、节奏和亮区；不要自动加深到灰暗脏色。

当项目采用上述流体方向时，使用以下验收顺序：

1. 固定轮廓单独看，确认无旋转、意外形变或顶部裁断。
2. 看完整循环的开始、约四分之一、二分之一及四分之三处，确认内部亮区的位置、范围或色彩关系确实改变；整体漂移或透明度闪烁不能冒充内部流动。
3. 在已选色域里比较明暗，优先通过浅色与亮白流动扩大对比；核对不会出现用户未选的深灰脏色。
4. 检查局部 blur 有强弱变化，颗粒细且不会污染正文；白底上仍看得到轮廓与内部层次。
5. 回看手机，确认画面比例、裁切、性能和静态降级。动效范围太小时先扩大内部运动场，避免盲目放大整个构图。

该配方来自一种具体视觉方向；品牌要求其他材质时换参数与验收目标，不复制其星形或蓝紫色。

## 3. Header 的重量与间距

默认展开、滚动后收成悬浮容器时，分别设计宽度、Logo 尺寸、CTA 高度和内边距。整体缩小后同步内部元素，避免仍是大按钮挤在小容器内。

导航项间距、右侧语言与 CTA 间距、容器内边距分别管理。几何值相等不一定视觉平衡，先满足用户确认的设计，再检查实际画面。锚点到达后标题不能被固定 Header 遮住。

按两种状态逐项核对：

| 问题 | 修改对象 | 验收方式 |
| --- | --- | --- |
| 导航 Tab 挤在一起 | 导航列表 gap，必要时收进菜单 | 所有项间距稳定，文字不被压成多行 |
| 语言与 CTA 过近或相距过远 | 右侧操作组 gap 与布局，不借用整行 space-between 撑开 | 二者仍是一组，与中间导航有清楚分隔 |
| 滚动容器左右显著比上下宽 | 四边 padding 与实际控件边界 | 用户要求一致时采用共同 token，再核对可见边距 |
| 收缩后仍又宽又重 | 容器最大宽度、Logo 与 CTA 尺寸 | 顶部和滚动态各看一张完整画面，文字仍清楚 |

菜单收起时只展示所需入口；手机的语言组件与导航若要求放进展开菜单，检查展开后可找到、关闭后不占默认 Header 空间。

## 4. 场景 Tab、自动进度与滚动聚焦

先确定主驱动是计时还是滚动；二者共存时明确优先级：

- 自动播放时进度条与内容切换一致，手动点击后更新选中状态与计时。
- 滚动聚焦时，明确进入、逐段推进、最后一项后释放和反向滚动行为。
- 不同时运行彼此争夺状态的计时器和滚动控制。
- 保留页面正常离开区块的路径，避免滚轮或触摸被无限捕获。
- 手机根据内容密度选择紧凑切换、普通分段展示或合适滚动方式，不机械复制桌面固定高度。
- 无需此交互的局部修改，不顺带引入整套滚动框架。

视觉状态分别定义“默认、hover / focus、选中、播放进度”，不能只用一块默认色冒充整个时间线。用户要求中性 hover 时用轻中性色反馈，已选项和进度继续采用确认的强调色或渐变；hover 不能覆盖选中状态。

分别设置区块标题 / 说明到 Tab 的距离、Tab 之间的 gap、Tab 到内容的距离，以及画面内部 padding。若标题贴内容，修区块间距；若画面太矮或背景只剩窄边，修展示区域与内部 UI 比例。验收点击每一项、等待自动推进、滚动到最后一项后退出，并检查新增场景不会沿用重复画面或漏掉时间段。

## 5. FAQ 和弹窗细节

FAQ 展开时核对问题、答案、图标、背景与分隔线的关系。分隔线若表示条目边界，应落在条目之间，不因展开变成卡片内部多余横线。按钮保留可识别名称和展开状态。

例如项目确认“默认第一项展开、每次只展开一项”后，实际执行：首次加载核对第一项 → hover / focus 任意问题 → 点另一项确认原项收起 → 反复切换并查看答案换行 → 在手机和价格页复查相同规则。同步问题与答案各自字号、颜色、padding 和 divider；不能只调折叠态截图。

分类弹窗首屏应能发现其主要内容。有产品时可显示产品数量与“查看产品”引导；没有产品时不显示无效按钮。弹窗尺寸由内容和视口决定，不固定沿用历史项目的像素宽度。

进入产品详情后能返回原分类；恢复列表和位置的方式与页面结构一致。处理关闭、Escape、焦点归还、背景滚动与弹窗内部滚动，避免返回后丢失用户上下文。

区分弹窗的两种离开路径：关闭 / 返回时把焦点还给原入口；点击“加入搭配”“前往询盘”等继续任务时，把焦点交给目标标题或首个控件，不能又被 close 回调拉回屏幕外的原卡片。实测两个路径，再用 Tab 确认能从正确位置继续操作；截图看起来跳转成功不代表键盘路径正确。

## 6. 动效实现与验证

优先复用项目现有动效技术。选取能表达效果且成本合理的属性；大范围 blur、滤镜和多层混合需在目标设备检查，不因视觉需求默认增加大量实时图层。

验证一整个循环以及点击、滚动与切换打断时的行为。用不同时间点的画面或实际播放确认效果；单张截图只能证明某一帧。检查 reduced-motion 下仍能理解内容并操作，自动运动不会遮住正文或造成布局跳动。
