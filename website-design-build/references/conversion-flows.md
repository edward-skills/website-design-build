# 询盘、留资、价格与登录

用于网站的实际转化路径。先区分当前任务是 UI 设计、可运行预览还是业务接入，再核对已有能力。

## 1. 给每个 CTA 明确动作

记录按钮文案、前置条件、目标、携带上下文、成功与失败状态。常见动作包括滚动定位、打开详情、登录后返回目标、提交表单、开始结账和联系销售。

文案与动作一致：“提交需求”应提交需求；“立即购买”应进入已接通的购买流程。用户明确只做 UIUX 时，可以做好状态和接入契约，但不能把空点击、打开邮件客户端或模拟成功当成业务已完成。

若任务本身是浏览、比较或搭配，浏览器保存和下载清单可以是完整结果，但界面必须准确说明作用范围，不称为已联系商家、已收到询盘或订单。切换一个字段会自动更换另一选择时，事先说明联动并反馈实际更新；不要让用户手选的产品被不知情地替换。

验证本地保存时实际刷新并查看恢复结果；验证下载时取得真实文件，核对产品、字段、中文编码与格式，而非只看到按钮存在。发布到另一个域名后，浏览器本地数据的作用范围也随 origin 改变；不承诺本地保存会自动跨站同步。

## 2. 独立站产品到询盘

按当前信息架构走完整路径：

1. 看见分类，理解分类差异。
2. 进入分类后发现产品列表，有清楚的列表入口或数量。
3. 查看具体产品、图片和相关规格。
4. 可以返回刚才的分类继续浏览。
5. 发起询盘时带入正确产品或分类，不清掉用户已填写内容。
6. 填写必要联系方式和需求，得到与实际提交方式一致的结果。

分类卡片与具体产品是两个层次，不把“编辑分类”误当成“发布产品”。产品数量多、为空或暂未发布时分别检查。

## 3. 留资表单的完整闭环

### 字段与顺序

- 从跟进所需的最少信息开始，例如可用的邮箱或手机；是否必须同时填写按业务决定。
- 需求、公司等可选字段在提交 CTA 之前出现，并明确选填。
- 不在提交完成后追加必填步骤，也不要求用户再点一次“联系我”才能生效。
- 标签、格式提示、错误信息与页面语言一致。

以“手机号或邮箱可联系，需求选填”为例，预期顺序为：联系方式 → 可选需求 → 提交 CTA → 保存成功反馈。分别测试只填手机、只填邮箱、两者都空、需求为空以及接口失败；不要用一个必填邮箱规则误拒绝只留手机的用户。其他业务字段按真实需求增减。

### 数据路径

确认接口、字段、存储位置、接收人和后续查看方式。没有接口时，先完成已授权的设计和接入层，说明业务缺口；本次已包含后端时实现最小必要接口，不因技术偏好额外引入 CRM。

状态至少涵盖相关的初始、校验失败、提交中、服务端失败和真实成功。服务端失败保留输入，提交期间避免重复请求；成功反馈必须基于实际接口结果，不能仅靠前端点击切换。

如果网站采用 WhatsApp 或邮件草稿引导，需要明确由访客在外部应用发送；“打开草稿”与“网站收到询盘”是不同结果。用户要求直接留资时，应接到保存流程。

### 跟进入口

mailto 依赖设备配置。后台可按使用场景提供网页邮箱写信、邮件应用和复制邮箱，核对收件人及参数。验证跳转不等于需要读取私人收件箱，也不需要实际发出邮件。

区分内部管理员联系方式、品牌公开联系方式与客户提交的联系方式，避免互相替换。

## 4. 价格页

核对套餐、价格、周期、额度、加量包、共同能力和 FAQ 的来源。文档与运行时不一致时分别记录展示要求和实际状态，不顺手修改计费逻辑。

### 价格事实与计算

将卡片、计算器、FAQ、登录摘要使用的套餐资料放在同一可维护来源，沿用已有计费数据；不要在每页各写一组数字。新静态站也可由一份资料生成页面与交互配置，不必为此增加后台。

- 分清按工作区、按席位、按用量计价；月均折算价与实际扣款周期同时可见。年付总额按已确认规则计算，例如“每席位月均价 × 席位数 × 12”；不能只换单价，仍显示月付总额。
- 最低人数、额度、优惠期限、退款与“永久免费”都是商业事实。零元不自动表示永久；估算控件的技术范围也不能写成未经证实的产品人数上限。
- 费用单位、一次应付金额与限制要在真实尺寸下可读，不因它们是辅助文字就缩成装饰小字。提供人数估算时，结果附近应有明确的继续入口。
- 有人数输入时检查空值、低于最低值、小数和恢复有效值。无效输入显示原因，并停止展示或明确标记旧总额、阻止携带旧选择继续；不要在失焦时悄悄改回默认人数。切换周期也不能绕过这一状态。

### 跨页选择

用稳定的套餐标识携带已选周期、人数与必要返回目标。核对卡片 CTA、估算器入口、登录摘要、“修改”和其他返回价格的入口；一条路径正确不代表其他链接也正确。直接打开页面、刷新和返回后，金额与选择应一致；未选择套餐时不强行显示付费意向。URL 参数做允许值校验，返回目标沿用应用允许的路由，不能任意跳转。

这些是展示与传递规则，不改变既有账户或计费含义。仅做界面时保留方案意向，不写成订阅已创建或支付成功。

CTA 状态根据已有业务契约设计：

| 用户状态 | 可用交互示例 | 要核对的上下文 |
| --- | --- | --- |
| 未登录 | 登录并订阅 / 购买 | 计划、周期、登录后返回目标 |
| 已登录 | 订阅 / 购买 | 实际 checkout、当前账户、可购买性 |
| 需要人工开通 | 联系销售 / 提交需求 | 能收到客户资料的真实路径 |
| 本次仅 UI，支付待接入 | 已设计的状态与可配置接入点 | 在交付说明中注明未接通，避免伪造成功 |

各档价格与共同能力需要清晰层级，能力图标可以表达不同含义，但优先复用已有设计系统。解释额度时保留决定购买所需的信息，删掉重复或与本页无关的内部实现说明。

共同能力区也需与确认设计对照底色、容器、图标语义和字阶；不能只核对三张价格卡就判定整页完成。用户要求不同能力用不同图标时，不继续全用 check；图标和文案均从同一已确认能力表匹配。

## 5. 登录页

先读已有登录方式、回调、目标路由、账号与地区规则。沿用真实 Google、手机号、邮箱等流程，不用静态假按钮替代现有功能，也不为改视觉新建一套账户系统。

新品牌只有产品材料、没有认证服务时，先完成页面与相关状态，准确说明接入缺口。若增加可体验示例，将它作为独立的演示入口，使用可识别的示例数据；进入示例不等于登录成功、账号创建或付费套餐开通。表单校验通过也不能显示“已发送登录链接”，除非实际服务确认发送。用户要求真实认证时仍需完成相应接入，不能用演示替代。

检查：

- 进入登录时保留语言、地区与允许的返回目标。
- 各登录方式切换后显示正确字段、验证和错误状态。
- 真实 OAuth 的配置、回调域名、cookie 与跳转分别核对，不能仅因预览失败推断正式站可用。
- 左侧营销画面与右侧表单的比例明确；Logo、标题和欢迎语避免重复堆叠。
- 桌面一屏展示按设计实现，同时允许小屏和软键盘场景访问所有表单内容。

左侧营销区与右侧登录区分别控制：

| 部位 | 操作 | 验收 |
| --- | --- | --- |
| 左侧画面 | 使用确认素材与构图，调整组内间距和比例，保持适当视觉分量 | 不能因修一屏高度把整片左侧缩成小图；也不重复堆满装饰 |
| 左侧标题 | 保留产品含义；按要求突出关键词；轮换 slogan 时预留稳定版式 | 切换不推动表单或造成整页滚动，所有语言仍自然可读 |
| 右侧品牌 | 按已确认组合展示图形与字标，清理重复的左上角 Logo 或 welcome 文案 | 身份清楚且没有无意义重复；不把字标删成仅一个图形 |
| 右侧控件 | 用现有设计系统按钮和输入框，并保留真实认证回调 | 不能因营销渐变色改成未经确认的按钮色；每种登录方式可进入对应流程 |

环境提醒、演示标签与接入说明优先放交付记录，只有用户确实需要判断时才进入页面。不要为解释本地预览限制擅自在登录页顶部加提示条、挤压布局或缩小营销区。

只需要产品访问权限时，先查具体权限模型，不把它扩大成创建运行实例、计费订阅或改变其他账户权限。

## 验收

在允许测试的环境执行与本次变更相关的真实路径，核对请求结果和必要的数据落点。UI 预览只报告 UI 已验收；接口、登录、支付或生产数据未验证时明确列出。测试数据使用可识别标记，保留或清理遵循用户约定。
