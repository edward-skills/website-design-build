# 少量品牌输入，直接做出第一版

当用户只给品牌介绍、网站内容和一些素材，没有 sitemap、设计参考或技术栈时读取。目标是让用户尽快打开一版有完整内容和真实交互的网页。这里的决策由 agent 完成，不转成一份要求用户填写的问卷。

## 1. 从原始输入确定三件事

- **卖什么 / 展示什么：** 品牌、产品或服务，以及现有材料能证实的差异。
- **给谁看：** 优先读取用户原话；没有明确客群但可合理推断时先按该假设执行并简短说明。
- **下一步做什么：** 浏览、比较、选择、了解、询盘或购买。先看用户目标与已有能力，再决定 CTA。

内部区分已知事实、可以调整的设计假设和必须待补的商业信息。不能为了“像一个完整品牌”自行添加注册商标符号、认证、销量、客户、产品参数或售价。已知缺价格与渠道时，不自动制作虚假的购买入口；用户明确要求真实询盘或购买时，也不能悄悄换成仅在浏览器保存的收藏功能。

按网站的目标补读对应模块，而不是把所有新站都当成单页展示。用户已给 SaaS 介绍并要求首页、价格与登录时，直接读 [转化流程](conversion-flows.md) 的价格和登录部分；自行从素材提取套餐、计价单位、周期和现有登录方式，把三页组织成一条访问路径，不要求用户另写功能规格。

## 2. 先看素材，再分配用途

查看实际图片，记录对象、横竖比例、主体位置、文字可放区域和产品对应关系。分配首屏、分类 / 产品、场景及补充细节；不要仅凭文件名选择或将一张产品图复制成多个不同产品。

原图保留在资料区，网页使用导出的适当格式和尺寸。核对首屏与产品详情是同一个产品版本。生成素材只在任务允许且确有需要时使用，并说明来源；不能将其当成真实产品的额外规格证据。

## 3. 用一张内部决策卡确定视觉方向

在一段简短记录里写清以下五项，然后直接实施：

| 决策 | 要落到的具体内容 |
| --- | --- |
| 气质与依据 | 从品牌语气、产品形态和素材推导，不默认套历史案例的风格 |
| 颜色与字体 | 主背景、文字、强调色的角色；可实际加载的字体、字阶和中文可读性 |
| 首屏构图 | 首要对象、文案位置、主 CTA，以及手机上如何保住主体 |
| 整页阅读顺序 | 每个区块增加什么信息，删去没有事实支撑的背书或重复口号 |
| 一个核心交互 | 如产品详情与返回、按用途比较、真实询盘；交互与用户目标一致 |

没有参考网站不构成开工阻塞。需要外部参考时聚焦一个具体设计问题，避免把简单建站变成漫长的风格研究。

## 4. 选择足够简单的实现

已有代码沿用现有栈。新站以内容呈现和浏览器本地交互为主时，优先考虑构建简单的实现，不为普通单页强制增加账户、数据库或完整框架。

使用环境中已就绪的工具完成预览与浏览器检查。不要仅为测试静态页面先安装另一套 CLI；某工具不可用时先查已有替代能力，避免让普通用户处理非必要环境配置。使用平台工具时仍遵守其文档和权限要求。

源文件保持可维护、资源路径可部署，不把生成素材的临时路径直接写进网页。

## 5. 尽早打开第一版，再用真实画面修正

完成有代表性的页面后启动预览并打开，接着补完其余内容与操作。首次审查至少回答：

1. 不滚动页面，能否理解品牌提供什么、主对象是什么、主 CTA 会做什么？必要的品类信息不能只有读不懂的装饰英文。
2. 手机上的主体是否完整、文字是否压住主体，是否需要独立构图？不能只改变 background-position 后就认为完成。
3. 全部区块标题与说明在窄屏是否仍有正确层级？“没有横向溢出”不等于标题没被挤成碎行。
4. 按真实显示比例看正文、FAQ、字段与帮助信息，不能只在整页缩略图中判断字号。
5. 核心任务实际完成后，界面、焦点、保存结果及下载内容是否正确？不要只测按钮能点。

细节分别参考 [布局与响应式](responsive-layout.md)、[交互](interaction-motion.md) 和 [实现](implementation.md)，只展开本次遇到的问题。

## 6. 交付用户现在能打开的入口

检查实际预览 URL 和对应版本。持久托管按当前约定执行；若只有本地预览，说明运行条件，不把已停止服务的 localhost 当作可用交付。托管页需要登录时，明确其访问范围。

最终先给结果和入口，必要时附一张能看清主要变化的截图。源码、素材来源、已验证操作与待接入能力放在项目记录中。不要让用户先读内部 brief 才能找到网页。
