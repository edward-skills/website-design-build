# 视觉设计与产品表达

用于整体视觉、首屏、区块精修、真实产品展示和设计稿组织。不包含 Logo 或 IP 创作。

## 1. 拆解参考，而不是套用外观

用户给出参考站时，观察实际页面和相关状态；不要仅凭品牌名或记忆推测。提取与本项目有关的机制：

| 观察维度 | 要记录的具体关系 |
| --- | --- |
| 首屏 | 文案与画面占比、视线焦点、主要 CTA、背景和内容层次 |
| 排版 | 标题与正文层级、行长、字重、字距、按钮与辅助字可读性 |
| 空间 | 容器宽度、上下节奏、卡片内部留白、元素之间的分组关系 |
| 颜色与材质 | 底色、前景、局部高光、阴影、模糊、颗粒的作用 |
| 产品表达 | 真实截图的取舍、浮层、局部放大、结果卡与人物的关系 |
| 交互 | 默认、hover、滚动、展开后及手机状态 |

参考用于说明设计机制；品牌色、内容、产品界面和用户手调继续按本项目确定。不要因参考用了大渐变或深色区，就在所有 section 重复使用。

## 2. 先锁定现有资产和版式约束

读取已确认的字体、色系、标识、图片、用户最新改动及已有设计系统。保留原有图形特征，不因画质低自行换成新 Logo；修整或重设计超出当前任务时单独说明。

按用途定义文字层级：主标题、section 标题、卡片标题、正文、按钮、标签、辅助信息。字体和字号由真实内容、语言、屏幕与品牌共同决定；不给所有项目硬编码一套数值。

检查字体实际可用、字重真实存在。中文与英文可使用不同字体角色；手工改过的 FAQ、价格说明、字标要覆盖到对应语言、断点和状态。转曲字标可以保留，但普通正文保持可编辑。

字体记录到用途与字重，而非只写一个家族名：中文正文 / 字标、英文标题 / UI、主 CTA、FAQ 问题 / 答案。使用渲染结果与实际字体信息核对，不让字体回退伪装成已加载。历史项目指定的 MiSans、Outfit 或 DM Sans 只属于其配置，新项目按自身品牌选择。

**分开调整可读性与框体重量。** CTA 字太小，先改字号、字重与文字对比；Header 太重，先改按钮高度、内边距、Logo 尺寸与容器宽度。不能用“大按钮外框”代替清楚文字，也不能把正文和 FAQ 统一缩小来让 Header 轻盈。

## 3. 建立首屏构图

先确定第一眼要看到什么：产品效果、品牌场景或真实工作成果。按项目选择大图 / 视频叠文案、左文右图或其他构图，不固定双栏模板。

具体处理：

- 确认标题、解释和 CTA 的阅读顺序，避免每层都在争抢注意力。
- 大幅图片先选主体与裁切，再决定文字位置和必要遮罩；检查手机上的主体是否仍完整。
- 产品组合画面先有一个核心界面或结果，再安排辅助卡片与头像，避免各自漂浮。
- 背景图形、图片、文字和 UI 分层，检查容器裁切是否误伤主体或光效。
- 首屏不能因装饰画面过高而让手机用户滑过大量空白后才进入内容。
- 英文标题需要压缩到项目期望行数时，先改写与调整容器，不对所有语言强制相同断行。

## 4. 制作真实但清晰的产品画面

从实际产品选取一个可理解的任务，例如输入需求、选择角色、运行任务、得到结果。可以省略导航、缩短示例、裁切局部，但保留足以识别产品的控件和工作关系。

- 将“任务 → 处理 → 结果”关联起来，角色头像配名称或任务提示，避免只有头像装饰。
- 核对画面和独立浮层是否重复同一个信息；每张辅助卡应增加一种解释。
- 控制核心 UI 与背景的比例，让背景仍有适当留白，不变成极窄色框。
- UI 内的按钮和输入框如果只是视觉展示，不添加可点击暗示或空点击事件。
- 允许使用合适的中性示例，但不要遗留无关地点、客户名称或敏感数据。
- “示意、placeholder、组件名”等制作说明放到设计备注或交接记录；不自动写进营销页面。必须向访客说明的产品限制则清楚表达。

组合画面的制作顺序：选核心真实 UI → 选一张能解释结果的卡片 → 对应头像 / 名称 / 任务提示 → 建立相邻分组 → 调整整体比例与背景留白。检查每个浮层是否提供新信息；同一角色或结果在多个位置出现，需要有内容理由，不能靠复制填空。

## 5. 业务场景、团队与教程

### 业务场景保持同一布局语法

一组场景使用一致的文案与画面方向、标题层级、展示区域边界和 Tab 关系。项目选择左文右图后，同组切换不随意反向；每个场景的画面仍须对应不同任务，避免第三、第四项误用同一素材。

场景记录包含稳定标识、标题、简短说明、产品画面、角色与结果。项数来自实际内容，不把“四类场景”写死在布局、标题或轮播逻辑里；新增一项后检查 Tab 容量、进度和场景资源对应关系。

### 团队与背书复用已确认的处理方式

用户提供了处理后的团队照片，就沿用其裁切、渐变蒙版、光效和边界语言；避免换回原图直排或重新生成人物外貌。成员姓名、语言与身份从资料核对，介绍不能在视觉层级上压过主要业务内容和 FAQ。

背书使用真实标识。比较的是可见图形的视觉尺寸与基线，不只是图片外框相同；留白很多的 Logo 需调整显示区域。角色素材检查关键轮廓与脸部是否完整，不因容器裁切只露一角；身份标识与场景照片分别决定 contain 或 cover。

### 教程保留分类，复用播放器

用户要“一个视频区域”时，保留教程分类入口，在同一个有设计边框的播放器中切换对应视频；不把多个分类删成一个视频。核对分类名、视频源与选中状态一一对应。缺视频源时保留接入位置并在交付记录注明，不模拟播放成功。

## 6. 编排整页节奏

观察首屏到 footer 的整体画面，而非逐张卡片判断：

- 产品展示、场景、背书、流程和 CTA 是否各有视觉角色？
- 图像比例、留白与背景变化能否提示内容进入新阶段？
- 是否连续出现过多同尺寸、同底色、同排列的卡片？
- 深色区块若合适，是否与内容相配，并同步文字、图标和边界对比？
- 团队介绍与 FAQ 的字号层级是否合理，背书 Logo 的视觉重量是否平衡？
- footer 的导航、联系、社媒与品牌是否完整成组，而非遗漏的尾部？联系信息与产品入口在明确区域排列；真实社媒 icon 保持统一视觉重量与已选定的填色 / 描边风格。邮箱图标有明确目标，二维码有可打开、关闭且手机可查看的展示方式。

精简遵循信息作用，不按固定 section 数量删减。用户要求保留的色块或流程先保留，再消除内部重复。

## 7. 组织可编辑设计稿

遵守用户选择的制作方式。用户需要方便手调时，使用普通图层与适当 Auto Layout，不强制提前组件化；已有共享组件需要复用时沿用对应规则。

画板按当前页面、语言、断点和必要状态组织。旧稿删除或保留按用户指示，不为“清理”丢失仍需对比的版本。备注放在独立区域，当前稿与候选稿要能区分。

## 验收

查看整页及关键区块实际截图或渲染，检查字体加载、素材版本、构图、裁切、对比、字号和空间关系。设计数据正确不能代替目视检查；仅有桌面首屏截图也不能证明其余区块已完成。
